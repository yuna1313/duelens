# DueLens

프론트엔드와 백엔드를 하나의 Git 저장소에서 관리하는 프로젝트입니다.
Git 저장소 루트는 현재 `duelens/` 폴더입니다.

## 폴더 구성

```text
duelens/
├── frontend/             # React + TypeScript + Vite 애플리케이션
│   ├── src/              # 화면 및 프론트엔드 소스
│   ├── index.html
│   ├── package.json      # 프론트엔드 의존성 및 명령
│   ├── eslint.config.js
│   ├── tsconfig*.json
│   └── vite.config.ts
├── backend/              # Java + Spring Boot 백엔드
├── package.json          # npm 워크스페이스 및 공통 실행 진입점
├── package-lock.json     # npm 의존성 잠금 파일
├── .editorconfig
├── .gitignore
├── .nvmrc
├── AGENTS.md
└── README.md
```

`node_modules/`는 npm이 생성하는 의존성 폴더이며 Git에서 제외합니다.
프론트엔드 빌드 결과는 `frontend/dist/`에 생성되며 Git에서 제외합니다.

## 프론트엔드 개발 환경

- Node.js 26 LTS (`.nvmrc`에 버전 고정)
- npm workspaces
- React + TypeScript (엄격한 타입 검사)
- Vite + ESLint

## 설치 및 실행

저장소 루트에서 실행합니다.

```sh
npm ci
npm run dev
```

프론트엔드 개발 서버는 <http://localhost:5173>에서 실행됩니다.
루트 명령은 `@duelens/frontend` 워크스페이스의 명령을 실행합니다.

## 프론트엔드 개발 범위와 구조

현재는 **화면과 사용자 흐름을 먼저 구현하는 단계**입니다. iClass 로그인·과목/공지 수집·AI 분석·서버 저장은 연동하지 않았습니다.

```text
frontend/
├── src/
│   ├── app/
│   │   ├── App.tsx               # 앱 조립과 URL에 따른 화면 선택
│   │   ├── routes.ts             # 지원하는 주소 분석·잘못된 주소 구분
│   │   ├── previewClock.ts       # 다음 분 경계의 시각 갱신
│   │   ├── usePreviewClock.ts    # 한국 날짜·예정 계산에 쓰는 현재 시각
│   │   ├── workspace.ts          # 기능 간 상태 전환·과제/검토/공지/이력/알림 통합
│   │   ├── workspacePreview.ts   # 같은 ID와 현재 값으로 초기 예시 조립
│   │   └── reminderPlan.ts       # 현재 과제·알림 옵션의 예정 시각 계산
│   ├── pages/
│   │   ├── connection/           # 학교 연결·수집 관리 화면 조합
│   │   ├── courses/              # 과목 화면 조합과 화면 전용 스타일
│   │   ├── notices/              # 공지 목록·원문 화면과 화면 전용 스타일
│   │   ├── not-found/            # 잘못된 주소 안내와 복귀 경로
│   │   ├── notifications/        # 알림센터 화면 조합
│   │   ├── reviews/              # 공지 변경 검토 화면 조합
│   │   ├── settings/             # 설정 화면·과목 백업 조합·확인창
│   │   ├── start/                # 서비스 시작 안내
│   │   └── tasks/                # 내 과제 화면 조합과 화면 전용 스타일
│   ├── components/
│   │   ├── layout/               # 여러 화면이 쓰는 레이아웃·메뉴
│   │   └── ui/                   # 공통 UI 요소·아이콘
│   ├── contexts/                # 앱에서 제공하는 공통 학기 선택 상태
│   ├── domain/                  # 여러 기능이 공유하는 학기 모델·검증
│   ├── features/
│   │   ├── connection/           # 연결 상태·수집 결과 병합·안내와 과목별 수집 UI
│   │   ├── courses/              # 과목 전용 components·hooks, 모델·검증·저장
│   │   ├── history/              # 버전별 변경 비교·조회와 타임라인 components
│   │   ├── notices/              # 공지 상태·검색·입력 검증과 전용 components
│   │   ├── notifications/        # 알림 조회·읽음·예정 목록·브라우저 권한 안내
│   │   ├── reviews/              # 변경 비교·날짜·대상·충돌 검증과 검토 폼
│   │   ├── settings/             # 알림 옵션 모델·검증·저장·전용 UI
│   │   └── tasks/                # 과제 전용 components, 모델·검색·분류
│   ├── mocks/                    # 화면 확인용 예시 데이터
│   ├── styles/                   # 전역 색상·글꼴·공통 컨트롤 스타일
│   ├── utils/                    # 업무와 무관한 순수 함수(날짜 등)
│   └── main.tsx                  # React 실행 진입점
└── tests/                        # 기능별 검증 및 표시 로직 테스트
```

화면 단위와 기능 단위를 구분하는 혼합 구조입니다. `pages/`는 화면을 조합하고, `features/`에는 해당 기능의 UI·훅·타입·로직을 모읍니다.
예를 들어 과목 입력은 `features/courses/components/CourseForm.tsx`, 브라우저 저장 상태는 같은 기능의 `hooks/useCourses.ts`, 검증과 타입은 `model.ts`, 저장 처리는 `storage.ts`에서 관리합니다.
전용 컴포넌트의 CSS는 컴포넌트 옆에, 화면 전체 스타일은 해당 페이지 옆에 둡니다.

코드 배치 기준은 다음과 같습니다.

- 앱은 페이지를, 페이지는 기능과 공용 코드를 조합합니다. 공용 코드에서 페이지·기능을 가져오지 않습니다. 서로 다른 기능의 조합은 페이지나 앱에서 처리합니다.
- 특정 기능에서만 쓰는 훅·상수·타입은 해당 기능 안에 둡니다. 실제로 여러 기능이 함께 사용할 때 공용 위치로 옮깁니다.
- `mocks/`는 화면 확인용 데이터입니다. 페이지에서 예시를 선택하며, 기능의 모델·저장 코드가 예시 데이터에 의존하지 않도록 합니다.
- `utils/`는 날짜처럼 목적이 분명한 순수 함수를, `lib/`는 도입한 외부 라이브러리의 공통 설정을 위한 위치로 구분합니다. `lib/`는 해당 코드가 생길 때 추가합니다.
- 학기 모델은 과목·과제·공지·공통 선택 UI가 함께 사용하므로 `domain/academicTerm.ts`에 둡니다. `contexts/AcademicTermContext.ts`는 앱이 제공하는 선택 학기와 변경 동작을 공통 UI에 전달합니다. 두 위치 모두 개별 기능을 import하지 않습니다.
- 공용 `api/`, `hooks/`, `constants/` 등은 실제 공용 코드가 생길 때 추가합니다. 폴더를 채우기 위한 빈 파일이나 중계용 `index.ts`를 만들지 않고 실제 파일을 직접 import합니다.

이 구성은 [Bulletproof React의 프로젝트 구조 지침](https://github.com/alan2207/bulletproof-react/blob/master/docs/project-structure.md)의 기능별 배치와 공용 코드 분리를 참고했습니다.
특정 연도의 단일 표준으로 취급하지 않으며, [Feature-Sliced Design](https://feature-sliced.design/docs/reference/layers)의 모든 계층을 도입한 구조도 아닙니다.
앱에서 생성한 메모리 저장소를 React의 `useSyncExternalStore`로 구독합니다. 페이지는 데이터와 동작을 props로 받고, 기능 간 조합은 앱에서 처리합니다. 과목과 알림 옵션도 앱에서 한 번 구독합니다. API 호출 계층이나 외부 상태 라이브러리는 아직 도입하지 않았습니다.
메뉴는 `#/tasks`, `#/notices`, `#/notifications`, `#/courses`, `#/connection`, `#/settings` 주소로 이동하며 새로고침과 브라우저 뒤로 가기를 지원합니다. 모바일에서는 과목·학교 연결·설정을 하단 ‘더보기’로 묶습니다.
상단 경로의 `내 워크스페이스`는 메인 과제 목록으로 이동합니다. 과제 상세·수정·이력의 `내 과제`, 공지 원문·검토의 `공지함`도 해당 목록으로 이동합니다. 모바일에서도 같은 경로를 제공합니다.
지원하지 않는 메뉴·설정 하위 주소·중첩 경로는 별도 안내 화면을 표시합니다. 유효한 상세 주소의 존재하지 않는 ID는 해당 화면에서 찾을 수 없다고 안내합니다.
날짜와 알림 예정 계산 기준은 다음 분 경계 및 창 복귀 시 갱신합니다. 자정이 지나도 현재 과제·공지·검토 상태는 보존하며 오늘·이번 주 분류를 새 한국 날짜로 계산합니다.

### 시작 화면

기본 주소(`/`), `#/`, `#/start`에서는 서비스 안내와 시작 방법을 표시합니다. 기존 화면 주소로 직접 들어가는 동작도 유지합니다.

- `직접 입력으로 시작하기`는 과목·수업 등록으로, `과제 바로 추가하기`는 빈 과제 등록 폼으로 이동합니다.
- `예시 화면 둘러보기`는 내 과제 목록으로 이동합니다. 시작 화면의 안내 카드는 화면 예시이며 실제 공지·과제 데이터가 아닙니다.
- 인하대학교 I-Class의 `학교 연결 화면 보기`에서 연결·수집 상황 예시로 이동합니다. 학교 로그인 입력·인증·공지 수집은 수행하지 않습니다.
- 데이터 안내에서 브라우저에 저장하는 과목·알림 옵션과 이 탭의 메뉴 이동 중 유지되는 과제·공지·검토·이력·읽음 상태의 범위를 확인할 수 있습니다. 후자는 새로고침하면 초기화되며 과목 백업에 포함하지 않습니다.
- 데스크톱은 안내·시작 선택을 좌우에, 모바일은 위아래로 배치합니다. 시작 화면은 `src/pages/start/`, 공통 브랜드 표시는 `src/components/ui/Brand.tsx`에서 관리합니다.

### 내 과제 화면

`#/tasks`의 `내 과제`에서 예시 과제와 직접 입력한 과제로 **화면 미리보기**를 제공합니다.

- 선택한 학기 안에서 `전체 기간 / 이번 주 / 이번 달 / 마감 미정`을 조회합니다. 한국 표준시의 마감 날짜가 기준이며, 이번 주는 월요일~일요일, 이번 달은 1일~실제 말일을 양끝 포함합니다. 적용한 날짜 범위를 화면에 표시합니다.
- 조회 과제·남은 과제·제출 완료·마감 미정 집계와 목록에는 같은 학기·기간·검색·과목·상태 필터를 적용합니다. 남은 과제는 제출 완료로 표시하지 않은 과제이며 작성 완료와 기한이 지난 미제출도 포함합니다. 제출 완료 건수도 실제 제출 시각이 아닌 마감일로 조회합니다.
- 마감 미정은 전체 기간에 포함하고 주·월 조회에서는 제외하며 별도 조회 버튼으로 안내합니다. 이번 주 일정에도 현재 조회 조건의 미제출 과제만 표시합니다.
- `과제 추가`에서 과목명·분반·과제명, 마감 날짜·시각, 제출 형식·분량·링크, 메모·진행 상태를 입력합니다.
- 목록에서 `#/tasks/<과제 ID>`의 상세 화면으로 이동하며, `수정`에서 입력 값을 복원해 변경할 수 있습니다. 등록·수정 후 같은 ID의 상세·목록·집계에 반영됩니다. 취소하면 기존 값을 유지합니다.
- 상세 화면에서 미시작·진행 중·작성 완료·제출 완료를 구분합니다. 상태를 바꾸면 목록과 집계가 함께 바뀌며 실제 학교 제출은 수행하지 않습니다.
- 마감 날짜와 시각의 미정 상태를 구분하며, 없는 시각을 임의로 확정하지 않습니다.
- 수정 중 마감 미정을 켜면 날짜·시각을 비활성화하고 이유를 표시합니다. 같은 입력창에서 다시 날짜 지정으로 전환하면 전환 직전의 입력값을 복원합니다. 마감 미정으로 저장하면 날짜·시각 없이 저장합니다.
- 필수 값·입력 크기·실제 달력 날짜를 검사합니다. 제출 링크는 제어 문자·계정 정보가 없는 HTTP(S) 주소를 허용하며, 직접 선택할 때 새 탭으로 열립니다. 메모는 HTML을 실행하지 않고 일반 텍스트로 표시합니다.
- 예시 숨기기는 예시 과제에만 적용하며 직접 입력한 과제는 유지합니다. 검색 결과 없음·과제 없음·찾을 수 없는 과제 화면과 모바일 배치를 제공합니다.

등록한 과목은 학기·과목명·분반을 보고 ID로 선택해 연결하거나 과목명·분반을 직접 입력할 수 있습니다. 연결된 과목의 이름·분반 변경은 과제 표시에도 반영합니다. 과목이 삭제되면 과제와 입력 당시 이름·분반은 보존하고 재연결 경로를 제공합니다. 학교 과목의 실제 연동은 후속 단계입니다.
과제는 앱 메모리 상태에서 관리합니다. 다른 메뉴를 다녀와도 유지되며 새로고침하거나 탭을 닫으면 초기화됩니다. 등록·실제 값 수정·진행 상태 변경을 이력에 기록하고, 값이 같은 저장은 중복 이력을 만들지 않습니다. 브라우저 저장 공간·서버에 저장하거나 학교로 전송하지 않습니다.

### 공통 학기 선택

사이드바의 학기 버튼, 모바일 상단 학기 버튼에서 연도와 1학기·여름 계절학기·2학기·겨울 계절학기를 선택합니다. 과목·과제·공지·검토·알림을 같은 선택 학기로 조회합니다. 상세 화면에서 학기를 바꾸면 해당 목록으로 이동합니다.

과제와 공지의 소속 학기는 등록할 때 선택한 학기입니다. 과제를 등록한 과목에 연결하면 그 과목의 학기를 따릅니다. 마감 날짜로 학기 소속을 추정하지 않으며, 같은 과목·분반이어도 다른 학기의 과제는 검토 연결 대상에서 제외합니다. 학기 전환은 기존 기록을 삭제하지 않습니다.

선택 학기와 과목은 기존 `duelens.courses.v1` 형식을 유지해 브라우저에 저장하며, 정규학기 데이터와 계절학기를 함께 복원합니다. 과제·공지 등은 같은 탭에서만 유지됩니다. 초기 예시는 현재 한국 날짜에 따른 기본 정규학기에만 제공하므로 다른 학기는 직접 등록하기 전까지 비어 있습니다. 학교 학사 일정은 아직 연동하지 않습니다.

### 공지함·원문 미리보기

`공지함`에서 예시 공지 목록과 원문을 살펴볼 수 있습니다.

- 제목·본문 검색, 과목 필터, 전체·검토 필요·반영 완료 구분, 읽지 않은 공지 수를 표시합니다.
- 공지를 선택하면 `#/notices/<공지 ID>`에서 원문과 검토 요약을 볼 수 있습니다. 목록과 원문 사이에서는 입력·필터·읽음 상태를 유지합니다.
- 검토 후보는 미리 작성한 예시입니다. 검토 완료 후에는 이 탭의 과제와 공지 처리 상태를 함께 반영합니다. 직접 붙여넣은 공지에는 임의의 후보를 생성하지 않습니다.
- `공지 붙여넣기`에서 과목명·제목·원문을 입력하면 해당 원문을 미리 봅니다. 직접 입력한 공지는 `분석 전`으로 구분하고 임의의 분석 결과를 붙이지 않습니다.
- 입력은 과목명 100자, 제목 150자, 원문 20,000자까지 허용하며 필수 값을 검사합니다. 붙여넣은 HTML을 실행하지 않고 일반 텍스트로 표시합니다.
- 검색 결과 없음·공지 없음·찾을 수 없는 공지 화면과 모바일 배치를 제공합니다.

공지 입력·읽음·처리 상태는 앱 메모리에서 관리하여 메뉴를 이동해도 유지합니다. 새로고침하면 초기화되며 브라우저 저장 공간·서버·AI로 저장하거나 전송하지 않습니다. 검색·필터와 완료 전 입력 폼은 화면을 벗어나면 초기화됩니다.
예시 데이터는 `src/mocks/notices.ts`, 공지 기능의 모델·전용 UI는 `src/features/notices/`, 화면 조합은 `src/pages/notices/`에서 관리합니다.

### 공지 변경 검토

공지함의 `변경사항 검토`에서 `#/reviews/<검토 ID>`로 이동합니다. `#/reviews`로 바로 들어가면 첫 예시를 표시합니다.

- 일반 변경, 날짜 확인, 연결 대상 확인, 직접 수정값 충돌의 네 가지 예시를 제공합니다.
- 마감 날짜·시각과 제출 형식을 현재 값과 비교하며, 항목마다 현재 값 유지 또는 공지 값 사용을 선택할 수 있습니다. 공지에 없는 값은 보존합니다.
- ‘다음 수업 전까지’와 같은 표현은 임의로 해석하지 않습니다. 날짜를 사용하려면 실제 달력 날짜와 직접 확인 여부를 검사하고, 시각은 입력하거나 명시적으로 미정으로 남깁니다.
- 연결 대상은 같은 과목·분반의 과제에서 선택하며, 대상이 불명확한 예시는 기존 과제 또는 새 과제 등록을 선택하고 확인해야 완료할 수 있습니다.
- 직접 수정한 값이 공지 기준값과 다르면 해당 항목을 자동 선택하지 않습니다. 검토 도중 대상 값이 바뀐 경우에도 이전 선택으로 덮어쓰지 않도록 검증합니다.
- 근거 문장과 원문 전체를 검토 화면 안에서 확인하며, 완료하면 선택한 값과 변경 항목을 결과로 표시합니다. 모든 현재 값을 유지한 경우도 구분합니다.

검토 완료 시 최신 과제를 다시 검증하고, 선택한 과제 값·검토 결과·공지 처리 상태·근거 원문을 보관한 이력·앱 내 완료 알림을 한 번에 반영합니다. 같은 후보를 다시 실행해도 과제·이력·알림을 중복 생성하지 않습니다. 같은 공지의 후보가 여러 개면 모두 완료된 뒤 반영 완료로 표시하고, 공지의 검토 링크는 남은 후보를 우선합니다. 모든 현재 값을 유지한 검토도 완료 기록을 남깁니다.
완료 결과는 메뉴 이동 중 유지하며 새로고침하면 초기화됩니다. 미완료 선택은 화면을 나가면 초기화됩니다. 결과 화면은 검토 완료 당시의 값이며 이후 직접 수정한 과제에 예전 결과를 다시 덮어쓰지 않습니다. 실제 AI 분석·학교 제출·서버 저장은 수행하지 않습니다.
검토 규칙·폼은 `src/features/reviews/`, 예시는 `src/mocks/reviews.ts`, 화면 조합은 `src/pages/reviews/`에 둡니다.

### 과제 변경 이력

과제 상세의 `변경 이력`에서 `#/tasks/<과제 ID>/history`로 이동합니다.

- 버전 번호·기록 시각·변경 유형을 최신순 타임라인으로 표시합니다. 공지 검토 반영·직접 수정·최초 등록을 구분하고 유형별로 조회할 수 있습니다.
- 실제로 바뀐 항목의 전후 값을 비교하며, 각 버전의 전체 값도 펼쳐 확인할 수 있습니다. 날짜·시각의 미정 상태를 구분합니다.
- 근거 문장, 연결된 공지, 기록 당시 보관한 원문을 확인할 수 있습니다. 원문 링크가 만료된 예시는 이동 링크를 제공하지 않고 당시 보관한 본문을 표시합니다.
- 이력이 없는 과제와 찾을 수 없는 과제를 구분합니다. 과제 상세·이력 사이 이동에서는 현재 과제의 입력·진행 상태를 유지하며, 과거 값을 조회해도 현재 과제는 바뀌지 않습니다.

초기 예시 과제는 현재 값과 일치하는 최초 등록 기록으로 시작합니다. 이후 과제 등록·직접 수정·진행 상태 변경·공지 검토 완료에서 버전별 이력을 생성합니다. 마감·제출 조건뿐 아니라 제목·과목·메모·제출 링크 변경도 기록하며, 공지 검토 시에는 당시 원문을 복사해 보관합니다.
기록은 이 탭의 앱 메모리에서 유지하며 브라우저·서버에 저장하지 않습니다. 과거 값으로 복원하는 기능은 후속 범위입니다.
이력 모델·전용 UI는 `src/features/history/`, 예시는 `src/mocks/history.ts`, 화면 조합은 `src/pages/tasks/TaskHistory.tsx`에 둡니다.

### 알림센터

`알림` 메뉴에서 `#/notifications`의 예시 알림을 확인합니다.

- 전체·읽지 않음·발송 예정 필터, 개별 읽음·읽지 않음 전환, 모두 읽음 처리를 제공합니다. 읽지 않은 알림이 없는 경우와 알림 자체가 없는 경우를 구분합니다.
- 읽음 여부와 발송 상태를 따로 표시합니다. 앱 내 알림·발송 요청·전달 실패를 구분하며, 읽음 처리로 실패 사유를 지우거나 요청 상태를 전달 완료로 바꾸지 않습니다.
- 예정 미리보기는 현재 과제·알림 옵션으로 계산해 가까운 시각순으로 표시합니다. 마감 날짜·시각이 정해진 미제출 과제의 미래 시각만 표시하며 하루 전·3시간 전 및 작성 완료 후 알림 옵션을 따릅니다. 마감 수정·제출 완료·옵션 변경 시 다시 계산합니다. 알림 설정을 읽지 못하면 예정 계산을 중단하고 설정 확인을 안내합니다.
- 알림에서 관련 과제 상세 또는 공지 변경 검토 화면으로 이동할 수 있습니다.
- 현재 브라우저의 알림 지원·권한 상태를 조회하고, 미허용·차단·미지원 시 앱 내 알림 안내를 표시합니다. `상태 새로 확인`은 상태를 다시 조회하며 권한 요청이나 발송을 수행하지 않습니다.
- 예시 숨기기·복원, 빈 목록, 모바일 메뉴와 알림 카드 배치를 제공합니다.

처음 제공하는 요청·실패 상태는 예시입니다. 검토 완료 알림은 이 탭의 작업에서 생성하고, 실제 알림 예약·요청·발송은 수행하지 않습니다. 예시 숨기기는 직접 작업에서 생성한 완료 알림을 숨기지 않습니다. 모두 읽음은 표시된 알림만 대상으로 합니다.
읽음 상태는 메뉴 이동 중 유지하며 새로고침하면 초기화됩니다. 알림 항목과 이력은 브라우저 저장 공간·서버에 저장하지 않습니다.
알림 기능의 모델·전용 UI는 `src/features/notifications/`, 예시는 `src/mocks/notifications.ts`, 화면 조합은 `src/pages/notifications/`에 둡니다.

### 학교 연결·수집 관리

시작 화면 또는 `학교 연결` 메뉴에서 `#/connection`으로 이동합니다.

- 기본은 미연결 상태입니다. 상황 예시에서 미연결·연결됨·인증 만료·일부 수집 실패를 구분해 확인할 수 있습니다.
- 연결·재연결 안내는 실제 연결의 예정 순서만 설명합니다. 계정·비밀번호를 입력하지 않으며, 버튼은 명시적으로 표시된 예시 상태만 변경합니다.
- 과목별 수집 상태, 마지막 시도·성공 시각, 보관한 예시 과제·공지·검토 건수를 표시합니다. 일부 실패 시 성공한 과목과 실패 과목의 기존 기록·성공 시각을 유지합니다.
- 과목별 재시도 예시는 해당 과목만 갱신합니다. 전체 갱신과 재시도 모두 실제 학교 요청 없이 예시 결과를 표시합니다.
- 미연결·만료 상태에서는 수집 결과 갱신을 막습니다. 재연결 예시는 기존 기록과 시각을 유지한 수집 대기 상태로 돌아가며, 별도 갱신 전에는 수집 성공으로 표시하지 않습니다.
- 예시 연결 해제는 확인창을 거치며 기존 기록을 보존한 수집 중단 상태로 바꿉니다. 취소·Escape로 닫을 수 있고, 닫은 뒤 관련 버튼으로 키보드 초점을 돌립니다.
- 연결 상태와 관계없이 기존 과제 열람·직접 추가, 공지함에서 붙여넣기, 내 과목 관리로 이동할 수 있습니다.

실제 학교는 연결되지 않았으며 공통 메뉴의 학교 미연결 안내도 유지합니다. 이 화면의 과목·기록은 직접 등록한 과목과 별개인 예시입니다.
화면을 벗어나거나 새로고침하면 예시 변경이 초기화됩니다. 예시 해제·초기화는 브라우저에 저장한 과목을 삭제하지 않습니다.
기능 모델·전용 UI는 `src/features/connection/`, 예시는 `src/mocks/connection.ts`, 화면 조합은 `src/pages/connection/`에 둡니다.

### 과목·수업 관리

`과목·수업` 메뉴에서 학교 연결 없이 과목을 직접 등록하고 수정할 수 있습니다.

- 연도·학기, 과목명, 분반을 등록하며 같은 학기의 동일 과목·분반 중복은 막습니다. 다른 학기나 분반은 별개로 관리합니다.
- 수업 요일과 시작 시각은 함께 입력하거나 모두 비울 수 있습니다. 시간표가 정해지지 않은 과목에 임의의 시간을 붙이지 않습니다.
- 학기별로 목록을 조회하며, 새로고침하면 과목과 선택한 학기가 복원됩니다. 날짜와 수업 시각은 한국 표준시(UTC+9)를 기준으로 합니다.
- 다른 창에서 먼저 수정된 내용을 감지하면 저장된 내용을 다시 불러오도록 안내합니다. 저장 실패 시 성공 메시지를 표시하지 않고 입력을 유지합니다.

과목 정보는 현재 브라우저의 `localStorage`에 저장됩니다. 브라우저·프로필·접속 주소가 다르면 별도 데이터이며, 브라우저 데이터를 삭제하면 기록도 삭제됩니다.
손상되었거나 지원하지 않는 형식의 저장 데이터는 자동으로 초기화하거나 덮어쓰지 않습니다.
현재 백엔드에는 기동 상태 확인만 구현되어 있으며, 과목 API·데이터베이스·기기 간 동기화와 마감 표현 해석은 아직 구현하지 않았습니다.

### 설정·데이터 관리

`설정` 메뉴의 `#/settings`에서 알림 옵션, `#/settings/data`에서 저장한 과목, `#/settings/privacy`에서 데이터 보관·AI 안내를 확인합니다.

- 마감 하루 전·3시간 전·작성 완료 후 알림 옵션을 `duelens.reminders.v1`에 저장하고 새로고침 후 복원합니다. 알림센터의 예정 미리보기에 적용하며 실제 예약·발송은 아직 연결하지 않았습니다.
- 브라우저 알림 권한을 조회하고 안내하며 권한 요청·발송은 수행하지 않습니다. 모델 학습용 제공은 비활성 상태이며 학습 데이터를 수집·전송하지 않습니다.
- 백업 대상은 `duelens.courses.v1`의 과목과 선택 학기뿐입니다. 과제·공지·검토·이력·알림·학교 연결 예시 및 알림 옵션은 과목 백업에 포함하지 않습니다.
- 버전이 명시된 JSON을 내보냅니다. 과목의 허용된 필드만 직렬화하며 다른 저장 키·인증 정보·알 수 없는 추가 필드는 내보내지 않습니다.
- 가져오기는 4MB 이하 파일의 형식·버전·과목·중복을 검증한 뒤 건수·학기·과목을 표시합니다. 명시적 확인 전에는 저장하지 않으며, 확인 후 과목 키 하나만 교체합니다. 빈 백업은 현재 과목도 비워진다고 안내합니다.
- 과목 삭제도 대상 건수·과목과 확인란을 거칩니다. 취소·Escape 시 유지하고, 삭제해도 알림 옵션·다른 저장 키·학교 원본은 변경하지 않습니다.
- 검토 중 다른 창에서 과목이 바뀌면 복원·삭제를 중단합니다. 손상된 데이터는 자동 초기화하지 않고 저장 실패 시 성공으로 표시하지 않습니다.

알림 옵션의 모델·저장·전용 UI는 `src/features/settings/`, 화면 조합과 과목 백업 어댑터·확인창은 `src/pages/settings/`에서 관리합니다. 과목과 설정의 기능 간 조합은 페이지 계층에서 수행합니다.

## 검증 및 빌드

저장소 루트에서 실행합니다.

```sh
npm run typecheck
npm run lint
npm run test --workspace @duelens/frontend
npm run build
npm run preview
```

현재 위 명령은 프론트엔드를 대상으로 합니다.
`build`는 타입 검사 후 `frontend/dist/`에 배포용 파일을 생성합니다.
`preview`는 빌드 결과를 로컬에서 확인할 때 사용합니다.
테스트는 Node.js 기본 테스트 실행기로 과목 등록·저장 실패 처리, 과제의 날짜·검색·등록·수정·제출 링크 검증, 공지 필터와 입력 범위·원문 보존, 변경 검토의 선택·날짜·연결 대상·충돌·동시 수정 검증, 이력의 버전 비교·조회·원문 보존, 알림의 읽음·발송 상태 구분·필터·예정 정렬·한국 시각 표시, 수집 실패·재시도·연결 해제·복구 시 기록 보존을 확인합니다. 알림 옵션 저장·충돌·실패 처리와 과목 백업의 손상·크기·중복 검증, 복원·삭제 시 대상 키 제한·실패 시 원본 보존도 검증합니다.
통합 상태 테스트는 과제 ID·현재 값·이력의 일치, 검토 결과의 일괄 반영·중복 실행 방지·수정 충돌, 새 과제와 직접 입력의 보존을 확인합니다. 알림 예정 계산은 한국 자정·월 경계, 지난 시각 제외, 마감·제출 상태·옵션 변경을 검증합니다.
주소 선택·오류 경로와 분 경계·한국 자정·지연 실행 후 시각 갱신도 검증합니다. 브라우저로 확인한 환경·흐름·수정 결과는 [프론트 전체 흐름 검증 기록](docs/frontend-qa.md)에 정리했습니다.
주·월의 연말·윤년 경계, 집계 기준, 마감 미정 전환 시 입력값 복원, 정규·계절학기 저장 호환과 다른 학기 검토 차단도 테스트합니다.
백엔드는 별도 터미널에서 실행합니다.

```sh
npm run dev:backend
npm run test:backend
npm run build:backend
```

백엔드는 JDK 25 이상에서 Java 25 호환으로 빌드하며 Gradle Wrapper를 사용합니다.
기동 상태는 <http://127.0.0.1:8080/api/health>에서 확인할 수 있습니다.
프론트엔드 개발 서버의 `/api` 요청은 백엔드로 전달됩니다.
자세한 내용은 [백엔드 개발 안내](backend/README.md)를 참고합니다.

## 프론트엔드 의존성 추가

```sh
npm install <패키지명> --workspace @duelens/frontend
npm install -D <개발용-패키지명> --workspace @duelens/frontend
```

의존성 변경 시 `frontend/package.json`과 루트 `package-lock.json`을 함께 커밋합니다.
잠금 파일과 의존성 설치는 저장소 루트에서 관리합니다.

## 소스 및 환경 변수

프론트엔드의 `@/`는 `frontend/src/`를 가리킵니다.
예: `import App from '@/app/App'`.

프론트엔드 환경 변수는 `frontend/.env.local`에 작성합니다.
브라우저에서 사용하는 값은 `VITE_` 접두사가 필요하며 빌드 결과에 공개되므로 비밀키를 넣지 않습니다.
환경 변수 파일은 Git에서 제외하고, 공유할 형식은 `frontend/.env.example`에 작성합니다.

## Git 및 배포 대상

- `feature/<기능명>`: 기능 개발
- `develop`: 최종 개발 테스트 환경
- `master`: 운영 환경

프론트엔드와 백엔드는 동일한 저장소에서 관리하며 각각 빌드·배포할 수 있도록 구성합니다.
자동 배포 파이프라인은 아직 설정하지 않았습니다.
